状态：按用户补充修订；首页方案待确认，应用功能尚未开始改造。日期：2026-11-08（用户时区）。

本轮只读分析现有工程、用户引用的“创建医院协会项目子文件夹”会话、参考页面交付截图，以及本机 WorkBuddy 安装结构。没有修改应用代码、启动测试或构建、操作管理端或发布版本。

## 1. 产品目标与边界

产品继续使用“超级建筑师 / SUPER ARCHITECT”。目标是一个可以从公开源码独立构建、无需工作台账号、无需自有管理服务器的本地建筑创作工作台。

- 启动直接进入本地工作区，首次仅选择数据目录、项目目录和可选的本机 Agent。
- 项目、对话、附件、资料库、偏好、任务记录和成果保存在用户选择的本地目录。
- 没有安装或连接 Agent 时，仍能进入工作台，管理资料、使用本地预览与编辑能力。
- 工作台界面、首页动画和本地业务不依赖互联网；AI 是否需要联网由所选 Codex / WorkBuddy 的运行方式决定。“本地工作台”不等于承诺这两个工具离线推理。
- 专业宿主及其授权仍由用户自行安装配置；安装器不捆绑商业软件、账号、凭据和未确认可分发的 SDK。

## 3. 本地化与账号模块处理

从主程序中移除工作台会员登录、刷新、退出、会员等级、积分、租户、管理端连接配置，以及必须经过这些身份才能使用的云项目、设备任务调度、远程配置和公告链路。

本地项目管理承接原云项目入口中的本机项目需求；图像、视频等创作入口直接进入本机能力页，按当前 Agent 实际可用能力显示。

软件更新改为公开发行渠道的可选检查或手动安装，不在启动时要求连接旧管理端。历史已发布安装包和签名记录保持原样。

保留回环地址限制、同源校验、本地进程随机访问令牌和文件范围约束。这些不向用户呈现登录流程，负责约束本地工具接口。

旧数据采用“备份后导入为本地工作区”，不自动合并原匿名区与不同会员目录。保留附件路径、项目关联和会话历史，重名采用独立工作区名称。实际迁移使用隔离副本验收，不接触生产服务。

## 4. Codex 与 WorkBuddy：沿用现有接入

沿用现有 Codex 和 `codebuddy` 两条接入路径，后者界面名称统一为 WorkBuddy；保留历史设置和会话兼容。本轮不新增 WorkBuddy 适配器、不新增反向调用桥、不引入官方云端 Open API。现有 MCP 与技能继续使用，相关改动仅随去登录和本地化需要开展。

### Codex

沿用本机 CLI，使用官方支持的非交互执行和 JSONL 事件，按任务绑定项目与输出目录。沿用工具自身账号配置，不另建模型代理或工作台收费账户。

官方依据：[Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)。

### WorkBuddy

直接复用现有 CodeBuddy 执行、流式事件、停止及产物处理。界面显示 WorkBuddy，底层配置继续使用 `codebuddy`，避免破坏已有数据。既有媒体和专业工具按真实可用能力展示。

## 5. 首页设计：微缩建筑设计院

### 视觉方向

保留石墨灰界面与品牌暖金，主视觉改成暖白、浅木、低饱和绿色的微缩建筑设计院。采用固定的等距斜俯视构图，按生产部门划分办公室，以中央总师办评审区连接各部门。采用局部隔墙、门牌和部门特色物件，保持人物及动线清楚，场景光照和界面色温协调。

参考用户指定工作台的空间布局、工位互动与人物生活感，重新设计建筑行业场景与原创角色。部门、人物及所选执行工具是不同概念；部门固定存在，不表示各有一个真实 Agent 在后台运行。

推荐不同发型、服装轮廓的原创建筑设计人物分布于各部门，可见人物数量随窗口尺寸控制。场景与人物以真实三维模型、骨骼动作及统一光照为目标；概念效果图仅用于方向沟通，最终以应用实际画面验收。

### 页面结构

1. 顶栏：项目选择、全局搜索、本机运行状态。
2. 主区：左侧约三分之二为事务所场景，右侧约三分之一为当前任务、待确认内容、成果入口。
3. 场景下方：始终可用的需求输入，选择 Codex / WorkBuddy、添加附件、发送任务。
4. 下方：最近项目与最近成果，保留继续工作的路径。
5. 侧栏：本地项目、设计助理、空间设计、成果交付、知识、画板、素材、工具、运行记录和设置；移除会员及云端项目入口。

首页使用真实项目和任务数据。首次启动展示空状态及操作引导，不填造项目数量、忙碌人数或百分比。

### 部门划分

| 部门 | 场景物件与人物动作 | 点击去向 |
| --- | --- | --- |
| 建筑设计所 | 建筑沙盘、草图台、立面图；绘图与推敲体块 | 建筑方案、建筑图纸、设计画板 |
| 规划与景观所 | 总平面沙盘、地形、景观植被；查看规划模型 | 场地资料、规划景观任务与参考 |
| 结构设计所 | 柱网与结构模型、结构图；校对图纸 | 结构相关资料、图纸与专业工具配置 |
| 机电设计所 | 管线模型及水暖电图纸；查看专业叠图 | 给排水、暖通、电气任务与资料 |
| 室内设计所 | 室内模型、材质墙、样板；选样与推敲空间 | 现有室内三维方案、素材与表现 |
| BIM 与数字技术中心 | 模型协同大屏、数字工作站；查看三维模型 | BIM / 建模软件连接、模型预览及自动化 |
| 总师办（中央评审区） | 评图墙、会议桌；讨论方案、传递图纸 | 项目进度、待确认事项、成果汇报及归档 |

上述是设计院的空间部门，不以五个工具功能替代部门。结构、机电等入口先复用现有任务与资料能力；尚未实现的专业计算、碰撞检查、校审及审签能力明确标注，不因场景存在就宣称可用。项目档案架与规范资料库作为各部门共享设施。

所有场景入口提供等价文字入口和键盘操作。点击人物查看关联任务或工位说明，不因点击就自动调用模型。

### 动画与任务状态

| 类型 | 行为 |
| --- | --- |
| 初次进入 | 约 0.6–0.8 秒完成场景显现，内容与输入可先操作 |
| 空闲 | 翻图纸、看模型、轻微姿态变化；偶尔短程走动，保持低干扰 |
| 真实任务执行 | 关联工位进入查资料、建模或整理文档动作；右侧显示实际事件 |
| 待用户确认 | 人物停止主要动作，右侧突出具体待确认问题 |
| 完成 | 当前成果以一次轻量反馈出现，可直接打开或定位文件 |
| 失败或取消 | 明确显示原因及可执行操作，停止对应工作动作 |
| 暂停与减少动态 | 可暂停场景；系统减少动态偏好下保留静态空间与全部功能 |

环境动作与运行状态分开：走动只表示场景生活感，任务标签只由真实事件驱动。默认同一时刻最多一位人物走动；起身、转向、步态、停步、坐下连续过渡，步幅与位移匹配，路线避开家具，手与键盘及图纸接触正确。

交互反馈约 120–180 毫秒，面板过渡约 220–300 毫秒。切换业务页面或窗口不可见时暂停场景，WebGL 不可用时显示原创静态视图与功能入口。

### 参考项目明确需要避免的问题

医院协会 v8.1 复查记录指出：早期存在手部悬空、高抬腿、长距离滑动、首屏裁切、文字过小，以及 2.5D 人物与三维房间在转向和光照上的差异。本方案将人物比例、桌椅遮挡、脚底接地、转身连续性和实际首屏完整性列为视觉验收项。

## 7. 确认后的实施与验收

实施顺序：公开源码清单与许可证 → 创建 GitHub 仓库并上传经检查的源码 → 等待设计院首页方案确认 → 本地核心解耦与旧数据迁移 → 现有 Agent 兼容回归 → 首页场景与真实状态联动 → 公开依赖复现与发行验证。

固定核心检查包括：无工作台账号启动、离线进入首页、项目与会话持久化、附件与产物、任务状态与停止、数据目录选择、本地访问边界。再覆盖本次受影响的设置、创作入口、两个 Agent、旧数据导入和动画交互，不擅自改成每次全量回归。

视觉在 1440×900、1366×768 及应用最小窗口验证：场景主要内容、输入区和关键按钮可用，人物不穿模，文字可读，暂停恢复可靠。录取连续动作证据，静态截图和接口测试不能代替动画验收。

开源验收要求：干净检出不依赖私有参考目录即可构建；无自有管理端仍能运行本地业务；Codex 与 WorkBuddy 分别完成真实任务并留下准确状态与成果证据。

所有后续构建、依赖缓存、临时目录、隔离运行数据、测试浏览器资料及安装包统一置于 E 盘，执行前显式设置，不回退 C 盘。源码修改仍位于本工程。涉及新发行时，继续执行已确认的验包与签名检查，保留旧版本基线。

本方案等待确认的核心方向：无账号本地工作台；沿用现有 Codex / CodeBuddy（界面称 WorkBuddy）接入；以按部门划分的微缩建筑设计院作为首页动画主视觉。源码公开与许可证准备已获单独授权，不据此提前开发首页。
