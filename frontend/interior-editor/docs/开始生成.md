# 开始生成本次室内方案

本文件由公开源码构建生成。目标是产出一个**绑定本次任务**的 `interior-studio/1` 场景 JSON，再由后端校验与组装成离线网页。

## 输入

1. 读取本次唯一配置（通常在任务目录的 `室内三维生成配置.json`）。
2. 核对 `taskId`、`primarySource.id/name/sha256/page/width/height` 与实际底图一致；PDF 还要核对 `rasterSha256` 与选定页。
3. 核对 `config.scalePolicy`；只有 `calibrated` 才允许使用两点标定比例。
4. 只使用本任务底图和风格参考。不得沿用样板户型、历史场景或其他任务的几何。

## 作者稿

在任务 `outputDir` 写 `本次方案.scene.json`，并另写识别核对记录。作者稿必须包含：

- `format: "interior-studio/1"`、`engineVersion`、`name`、`revision`、`isSample: false`
- `source.name` 与本次底图名称一致；`source.imageData` 写唯一占位符 `workbench:primary-source`（不要复制大图 base64）
- `generation` 精确写入任务/底图/哈希/页码
- `drawing`：原图像素尺寸、原点、米/像素比例、`estimated` 或 `user-calibrated`
- `architecture`：真实墙段、地面、顶面、门窗；每个对象有米制 `pos`/`size` 和 `sourceEvidence`
- `rooms`：真实房间边界；没有识别依据时不要虚构
- `schemes`：`base`、`mid`、本次已选风格；风格方案可含家具和 `surfaceOverrides`
- `style`：必须是本次已选方案之一
- `delivery: {stage: "design-draft"}`
- `recognition`：如实写 `needs-review` 与未解决项
- `assumptions`：列出估算、未描绘开口、无法从图面确认的假设

不要伪造 `styleAudit.screenshots`、视觉验收或实测尺寸。

## 后处理

带占位符的作者稿不要直接运行严格校验或网页组装。后端 `collect` 会核验原图字节/哈希和 PDF 选页位图，确定性注入 `source.imageData`，再运行 `场景校验.cjs` 与 `交付阶段校验.cjs`，最后生成离线 HTML。

若要手工描绘房间，使用工作台的描绘流程；后端会写入 `recognition.summary` 说明“未进行 AI 识别”，不要改写为自动识别结果。

## 禁止

- 不下载或复制参考产品的固定编辑器/技能/模型/纹理。
- 不调用外部生成 API、不上传底图、不访问生产服务。
- 不为通过校验而修改 `task.json`、配置、数据库或来源哈希。
- 不把草案标记为 `delivery-ready`，除非确实完成了核对、验收和截图证据。
